Astra CAD Cost Model

Is the API a bad idea because running it in-app is cheaper? In-app is cheaper in dollars and much more expensive in everything else. The number that will surprise you is the 272k cliff — cross it on one request and the entire request re-bills at double.

Use the API. Prune context every iteration. Never use fast mode.

Fast mode is roughly 2× the price for ~2.5× the speed, and nothing in a CAD run is latency-sensitive. Pruning is not an optimisation here, it is what keeps you off the long-context rate for the back half of every run.

One run, three ways
Why in-app loses despite being cheaper. Marginal cost on the $200 plan is about $0.25/message, so a 25-iteration run is ~$6 of quota. But you become the render loop: copy code out, execute, render views, re-upload — 3–5 minutes × 25, so 1.5–2 hours of manual work per run. Above roughly $7/hour for your own time, the API is cheaper. Three tasks × three attempts is a 15-hour week of clicking.
And the headline benchmark is a tools number. Astra scores 95.9% on BenchCAD mean voxel IoU reconstructing 3D objects from multi-view renders by writing CAD code — versus 83.3% for GPT-5.6 Sol and 84.3% for Claude Fable 5.1. That is a closed-loop-with-tools result. Break the loop and you are sampling a different, worse distribution.
Rates: $10/M in, $50/M out standard; $20/M in, $75/M out once a single request’s input reaches 272k. Sources: OpenAI, BenchCAD writeup. Working: 04-astra-cad/docs/cost-analysis.md
